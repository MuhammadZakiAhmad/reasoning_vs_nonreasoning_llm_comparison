**Lessons learned**:
- **Reframing the question can be cheaper than fixing the measurement.** Two sessions were spent fighting the phase confound — trimming windows, matching lengths — when the user's reframe (compare shape, not amount) removed the confound rather than compensating for it. The mass question was never the experiment's purpose; it had been inherited from the first version of the report.
- **A control comparison is worth more than a caveat.** C1 (thinking vs answering, same model) turns "the phase might be confounding this" into a measured number, and it also became its own result — the phase effect is bigger than the model effect.
- **Verify the control's size before believing the result.** The ordering matters: if C1 had come back large, C2 would have been void. Running the yardstick first is the same cheap-tripwire discipline that found the eos bug.
- **A test that cannot distinguish two code paths is not testing either of them.** Two breakages were initially missed because every stub happened to make both paths agree; the fix was a stub where only one path can succeed. Build the adversarial stub, not the convenient one.
- **A crashing harness is worse than a failing one.** Two breakages made the suite die mid-run, which skipped every later check and looked like "no output" rather than a regression. Guard the assertion so the run always reaches its summary.
- **Check the expectation before the code, again.** One new test asserted `shape[0] == 1/3` while the check directly beside it asserted the vectors were `[1/6, 1/3, 1/2]`. Same lesson as S2 — it is now the third occurrence, and it is always the expectation.
- **A token is not a string.** `</think>` is three tokens here, and `decode()`'s default would have silently deleted it. Search token IDs first; when text is needed, say explicitly what to do with special tokens.
